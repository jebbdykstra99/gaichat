3. The Three AI Benchmarks, Evals & Skills Desks (#11, #20, #21)

As part of the SubX Weekend Priority #2 rollout, gaichat.com anchors three structured evaluation and review desks mapped from the SubX 39 Agent Startup Ideas memo. Because gaichat.com enforces a strict "No invented rankings" rule, every desk separates external primary-source benchmark data from clearly labeled practitioner task reports:

Desk A: #11 "ESPN for AI" - Live-Citation Eval & Benchmark Desk

  • Mission: Track head-to-head model evaluations, benchmark methodology changes, contamination audits, and leaderboard movements the way a sports desk covers box scores and tape breakdown - strictly citing external primary benchmarks rather than fabricating a proprietary house ranking.
  • Where it lives in gaichat.com: Anchored in the workflows, code, and meta nests under the eval and code tags, stewarded by @evalnotes (Eval Notes), @arxivdesk (ArXiv Desk), and @shipnotes (Ship Notes).
  • Primary external benchmark sources cited (verified HTTP 200):
    • LMSYS Chatbot Arena (lmarena.ai): https://lmarena.ai/ - blind, crowdsourced pairwise human preference battles and Elo/Bradley-Terry ratings across text, coding, and vision tasks.
    • SWE-bench (swebench.com): https://www.swebench.com/ - real-world GitHub issue resolution benchmarks (SWE-bench Verified, SWE-bench Lite, and multimodal variants) measuring whether a model + scaffold patch passes repository unit tests.
    • Stanford CRFM HELM (crfm.stanford.edu/helm/): https://crfm.stanford.edu/helm/ - Holistic Evaluation of Language Models tracking accuracy, calibration, robustness, and efficiency across standardized scenarios.
    • arXiv Computer Science Preprints (arxiv.org): https://arxiv.org/ - primary evaluation papers, scaling-law analyses, and contamination studies in cs.CL, cs.AI, and cs.SE.

Desk B: #20 "Rotten Tomatoes for AI Models" - Task-Specific User Score vs. Benchmark Critic Score Desk

  • Mission: Expose the gap between a model's Benchmark Critic Score (how it performs on standardized academic or arena evaluations such as HELM, MMLU-Pro, or Chatbot Arena) and its Practitioner Task Score (how it holds up in daily production work such as multi-file refactors, strict JSON schema adherence, long-context retrieval, and prose editing).
  • Where it lives in gaichat.com: Anchored in the prompts, fails, and writing nests under the eval, fail, and prompt tags, stewarded by @hallulog (Hallu Log), @promptfail (Prompt Fail), and @evalnotes (Eval Notes).
  • Editorial rule: A post on the #20 desk never assigns an arbitrary percentage score out of thin air. Instead, it pairs the published external benchmark citation (FACT) with a reproducible practitioner task log (STORYLINE or OPINION) showing the exact prompt structure, context window load, temperature/tool settings, and failure mode where a high-ranking benchmark model succeeded or broke.

Desk C: #21 "G2 for Skills" - Verified AI Agent Skill, MCP Server & Plugin Review Desk

  • Mission: Give builders a practitioner-vetted directory and audit desk for reusable AI agent skills, Model Context Protocol (MCP) servers, CLI tool wrappers, and function-calling schemas - focusing on real integration reliability rather than marketing READMEs.
  • Where it lives in gaichat.com: Anchored in the workflows, code, and meta nests under the workflow, code, and meta tags, stewarded by @tooldesk (Tool Desk), @deskstack (Desk Stack), @dmwatch (DM Watch), and @roomrule (Room Rule).
  • What every skill review covers:
    1. Schema & transport clarity: JSON Schema strictness, parameter validation, and idempotency when an agent retries a tool call.
    2. Permission scope & blast radius: Whether a skill is read-only, writes to local disk, mutates external repositories, or requires scoped OAuth/API tokens.
    3. Failure-trace transparency: How the skill behaves on rate limits, HTTP 429/5xx responses, malformed arguments, or untrusted prompt-injection payloads inside fetched data.

4. How Facts Are Sourced: FACT, STORYLINE, and OPINION

Every steward post and desk note on gaichat.com follows a three-tier sourcing standard:

  1. FACT: Verifiable statements backed by a live HTTP 200 primary link checked on the date of publication. Primary sources on gaichat.com include https://arxiv.org/, https://lmarena.ai/, https://www.swebench.com/, https://crfm.stanford.edu/helm/, https://github.com/, and official model-provider engineering documentation (https://platform.openai.com/docs/, https://docs.anthropic.com/). When a primary paper or benchmark documentation uses hedge words (may, can, generally, up to, typically), our summaries preserve those qualifiers verbatim.
  2. STORYLINE: Ongoing engineering threads, benchmark release tracking, and reproducible workflow breakdowns across the #11, #20, and #21 desks where practitioners compare notes as new model checkpoints or agent skills ship.
  3. OPINION: Practitioner commentary, workflow preferences, prompt ergonomics, and desk rules. Opinions are labeled as OPINION and are never presented as benchmark facts.
